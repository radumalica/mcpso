# Risk Register: Import and Registry Launch

Likelihood / impact: L low, M medium, H high (judgement, not measured). Owner to be assigned.

| ID | Risk | L | I | Mitigation | Residual / trigger |
|---|---|---|---|---|---|
| R-01 | **GitHub API limits** throttle collection and enrichment (a shared 5,000/hour budget was exhausted once during the audit; enrichment needed ~200 batches) | H | M | token via env; bounded concurrency; backoff with jitter; resumable checkpoints; GraphQL batching; cache; run off-hours; dedicated token for the importer | rate-limit waits > planned window → pause and resume |
| R-02 | **Upstream keeps growing and changes** (925 issues in the first 16 days of Oct 2026; edits, deletions, transfers; 595 numbers unretrievable) | H | M | incremental sync by watermark; content hash revisions; mark vanished records; reconcile each run; define a cut-off date for the launch dataset | counts drift between runs → expected, reported |
| R-03 | **Data quality**: free-text extraction errors, template/bulk submissions, look-alike repos (CLIs, skills, scanners), registry-only evidence (1,930 of 3,502 eligible) | H | H | rule IDs and evidence stored; evidence tiers; bulk-approval limits; stratified hand checks; N-rules never auto-reject; content-type taxonomy | any stratum false-positive rate above threshold blocks bulk approve |
| R-04 | **Duplicate/merge mistakes** (shared packages across repos, monorepo subpaths, renames) | M | H | no merge on name similarity; probable matches queued; reversible merge history; split action | wrong merges found in review → tighten rule, re-run |
| R-05 | **Content-rights and licensing**: issue text, READMEs, logos belong to their authors; Apache-2.0 on the code does not cover them; upstream terms unknown | M | H | tier model; facts-only plus original summaries; internal-only raw store; counsel review; takedown path; no logos by default | legal opinion pending → hold public launch |
| R-06 | **Personal data** (author handles, contact details in issues) | M | M | store handle only for attribution; restrict raw access; opt-out and deletion path; retention limit | privacy review pending |
| R-07 | **Security**: malicious or misleading entries (pipe-to-shell installs, hidden Unicode, loopback endpoints, impersonation of official scopes), prompt-injection text in issue bodies | M | H | flags block bulk approval; sanitised rendering; never execute or follow imported instructions; no unreviewed LLM use; evidence levels; no "verified" claims | any flag → manual review |
| R-08 | **Application security debt** (public write routes, anon key as write credential, vulnerable dependencies) undermines the registry's trust | H | H | Phase A is a hard prerequisite: R01-R05 from the audit; RLS default-deny; CI gates | launch blocked until Phase A exit |
| R-09 | **Moderation workload**: 1,353 needs_review + 228 ambiguous + approval of thousands of eligible candidates by a small team | H | H | bulk tools with preview and undo; prioritised queue (evidence strength, stars-agnostic); phased publication waves; batch by submitter family; define a launch subset | queue age > target → pause new intake |
| R-10 | **Takedown/removal handling**: 7 removal requests, 6 unmapped; owners may object after publication | M | M | published process; ownership proof; suppression list checked on import; holds before publication | SLA missed → escalate |
| R-11 | **Misleading trust claims**: eligible ≠ safe; users read listings as endorsement | M | H | wording rules; evidence level and date on every listing; no "verified" until a documented procedure exists; disclaimers | complaint → review wording |
| R-12 | **Perceived affiliation** with the upstream project or confusion with its brand | L | M | own brand/domain; no upstream marks; non-affiliation statement; attribution only where required | none |
| R-13 | **Importer defects** (no client tests yet; pagination/retry bugs; regex ReDoS on untrusted text) | M | M | tests listed in the strategy; size caps (100k chars already); timeouts; fuzz tests | fail CI |
| R-14 | **Scope creep** delaying launch (advanced features before the registry works) | M | M | Phase E gated; launch scope fixed; checklist exit criteria | review at each phase gate |
| R-15 | **Registry dependency** on third-party services (GitHub, optional official registry) at refresh time | M | L | cached facts with retrieval dates; graceful degradation; no runtime dependency on upstream project | outage → serve stale with date |
| R-16 | **Stale listings** after publication (archived, abandoned, transferred repositories) | H | M | scheduled re-checks; stale/unavailable states; visible last-checked date | check backlog grows |
| R-17 | **Cost/ops** (hosting, runner, storage) not estimated | M | M | estimate before Phase D; budget caps on any paid API | unknown until estimated |
| R-18 | **Publication-boundary bypass**: a direct database write, bulk action or API call publishes an unreviewed, flagged, held or suppressed candidate | M | H | gates P1-P8 enforced in the database (guard triggers, transition functions), bulk guardrails (bound 500, count check, exclusions that cannot be cleared in bulk, undo), `public_listing` as the only client-readable object; JS gate tests run now, SQL suite must run on staging before any load | SQL suite never executed yet: treat as unverified until run |
| R-19 | **Count misinterpretation**: figures of different units (records, projects, repositories, annotation entries) are compared or summed, leading to wrong expectations or wrong reports | M | M | unit-explicit summaries, 39 reconciliation identities, definitions table, corrected earlier statements (`import-count-reconciliation.md` §4) | recurring: any new summary must carry units |
| R-20 | **Upstream drift during the project**: records appear, vanish and are edited within hours (8 new, 1 vanished, 3 body edits in 2 h 20 min) | H | M | content-hash revisions, fixed cut-off date (D9), incremental sync, reviewed basis = a named snapshot | accepted |
| R-21 | **Unverified SQL**: migrations and RLS assumptions (owner role bypass, `auth.uid()`, trigger behaviour) have not been run | H | H | run the draft migrations and tests on a disposable Postgres in CI before relying on them; second-person SQL review | blocks Phase B exit |
