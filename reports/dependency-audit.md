# Dependency Audit

Audit date: 2026-10-16. **No dependency was upgraded or changed.** The app's own pinned dependencies were installed with `pnpm install --frozen-lockfile --ignore-scripts` (lifecycle scripts disabled; the installed tree is only used to run audit tooling).
Raw outputs: `reports/evidence/pnpm-audit.txt`, `pnpm-audit-prod.txt`, `npm-audit.txt`, `pnpm-outdated.txt`, `npm-ci-dry-run.txt`, `unused-deps.txt`, `advisories-by-package.txt` (generated by `tools/audit/advisory_by_package.py`).
Advisory data comes from the npm registry audit endpoint as queried on the audit date; registry facts (deprecations, latest versions) were read with `npm view`.

## 2. Findings

### D-01 (Critical): `next@15.0.4` is affected by 37 advisories, 4 of them critical

`pnpm audit` lists, for `next` alone: 4 critical, 11 high, 18 moderate, 4 low. The ones that matter most for this app's shape (App Router, Server Components, edge runtime, Image component not used):

| Advisory | Severity | Relevance here | Fixed in |
|---|---|---|---|
| GHSA-9qr9-h5gf-34mp, RCE in the React Flight protocol | critical | Applies to any App Router app using React Server Components: **this app**. Exploitability on a Cloudflare edge deployment is unverified | 15.0.5 |
| GHSA-f82v-jwr5-mffw / CVE-2025-29927, middleware authorization bypass | critical | The app has **no middleware** → not exploitable as-is; becomes relevant the moment auth middleware is added | 15.2.3 |
| GHSA-p293-qw3h-jr36, unauthenticated RCE on Windows-hosted servers | critical | Not applicable on Linux/Cloudflare | 15.5.24 |
| GHSA-2xp9-vwfh-vxw4, RCE in Image Optimization API | critical | App does not use `next/image`; verify default `images` config before dismissing | 15.5.24 |
| 11 × DoS (Server Components, Server Actions, connection exhaustion) | high | Reachable on any public route | up to 15.5.21 |
| SSRF (rewrites, WebSocket upgrade, Server Actions on custom servers) | high | No rewrites/custom server in use → mostly N/A | up to 15.5.21 |
| Cache poisoning / cache-key confusion (SSG/ISR, RSC) | moderate/low | Pages are dynamic and uncached → limited | up to 15.5.27 |

* **Target:** `next@^15.5.28` (the newest 15.5.x on the registry; every `next` advisory in the report lists a fix at or below 15.5.27). Stay on 15.x for the first fix, since Next 16 (latest `16.4.2`) is a major jump.
* **React:** `react`/`react-dom` `19.0.0` → latest 19.0.x/19.1.x patch (19.1.10 exists) — the Flight/RSC fixes ship in React as well; pin both to the same version.
* **Breaking-change risk:** low within 15.x (App Router APIs used here: `generateMetadata`, async `params`/`searchParams`, `runtime="edge"`).
* **Tests required:** build + smoke render of `/`, `/categories`, `/category/x`, `/server/x`; **immediate**.

### D-02 (High): `@cloudflare/next-on-pages@1.13.6` is deprecated; the vulnerable subtree comes mostly from it and from `vercel`

* The registry deprecation message reads: *"Please use the OpenNext adapter instead: https://opennext.js.org/cloudflare"* (`npm view @cloudflare/next-on-pages deprecated`). Its dependency chain contributes `wrangler`, `esbuild`, `undici` (15 advisories), `node-forge` (8), `js-yaml`, `nanoid`, `defu`, `braces`, `picomatch`, `ws`, `@fastify/busboy`, `cookie`.
* `vercel@39.1.1` is a **dev dependency of a project that deploys to Cloudflare**; it is the sole source of 7 vulnerable packages (`tar` with a critical + 8 high, `path-to-regexp`, `semver`, `ajv`, `debug`, `diff`, `@tootallnate/once`) and the largest source of install-time supply-chain surface. Nothing in the repository references it. **Remove** (immediate; no breaking risk).
* Decision required before upgrading: choose the hosting target (see `target-architecture.md`). Either migrate to `@opennextjs/cloudflare` (current `1.20.12`) or drop the edge adapter and deploy on Node. Do not upgrade `next-on-pages`.

### D-04 (High): lockfile inconsistency: two lockfiles that disagree

`package-lock.json` pins `next@15.0.3` while `pnpm-lock.yaml` pins `15.0.4`; `npm ci` **fails** with `ERESOLVE` (a `@cloudflare/workers-types` peer conflict; `npm-ci-dry-run.txt`). The README instructs `pnpm install`, `Makefile`/scripts use `pnpm`, so `package-lock.json` is stale. A contributor running `npm install` gets a different tree. **Action:** delete `package-lock.json`; set `"packageManager": "pnpm@10.x"` and `engines.node`; add `pnpm install --frozen-lockfile` to CI. `pnpm install --frozen-lockfile --lockfile-only` passes, so `pnpm-lock.yaml` itself is consistent with `package.json`.

### D-06 (Medium): supply-chain posture

* **Lifecycle scripts:** the root manifest has none (`lifecycle-scripts.txt`). Dependencies may carry their own install scripts; this was **not enumerated** (`pnpm ignored-builds` returned no usable output, see `ignored-builds.txt`). Installing with `--ignore-scripts` was sufficient for every audit task (type-check, build of a patched copy, audits), so none of these needed install scripts. When the real deployment toolchain is chosen, record an explicit `pnpm.onlyBuiltDependencies` allow-list and review each entry.
* **Dependency confusion:** the package name `navfast` is not scoped and the project is `private: true` (cannot be published accidentally). No registry overrides, no `.npmrc`. Low risk.
* **`next-dev: link:@cloudflare/next-on-pages/next-dev`** is a link-protocol dev dependency to a path inside another package: unusual, brittle, and used only by a commented-out call in `next.config.mjs`. Remove with the adapter decision.
* **No Dependabot/Renovate, no CI audit gate.** Add both.

### D-07 (Info): runtime versions

No `engines`, `.nvmrc`, `.node-version` or `packageManager` field exists, so the supported runtime is undefined (the audit ran on Node 24.20.0 / pnpm 10.26.0 / TypeScript 5.7.2; build and type-check results above are for that combination). `@types/node@20` suggests Node 20 was intended; Node 20's scheduled end-of-life is April 2026 (per the Node.js release schedule; not re-queried), so choose an LTS that is current at launch.

* Peer-dependency conflict analysis was limited to the `npm ci` failure.
